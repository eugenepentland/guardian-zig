# Guardian-Zig — High-Value Additions Audit

**Date:** 2026-07-08
**Method:** Three parallel investigations — (1) archaeology of `eda` (the production consumer:
114k LOC, 856 tests, 551 commits in 30 days), (2) a feature inventory of guardian-zig as of
`2864846`, (3) a capability matrix against the sibling guardians (Gleam, Rust, SvelteKit).
Every load-bearing claim below was re-verified against current source before inclusion.
**Scope:** This is a *what to add* audit. The 2026-07-02 `AUDIT.md` was the bug audit; its four
P0s are all fixed (test-root drift guard at `src/check.zig:265`, container-recursive AST queries
at `src/ast/decls.zig` via `parser.zig:43`, fail-closed walker at `src/walk.zig:56`, tags-on-tests
at `src/spec/matcher.zig:111`).

---

## Executive summary

Since the 2026-07-06 audit, the recommended dynamic tier shipped: `mutate` (fast + `--full`
ratchet), `change-classification`, `--against`, plus `ban-secrets`, `stack-escape`,
`unsafe-ops-budget`, `[[allow]]` config exemptions, parallel check workers, and a skip-cache that
includes the guardian binary identity. The static layer is in good shape.

**The headline finding is an adoption gap, not a feature gap.** The two features aimed at the
bug class that actually ships (behavioral bugs — ~80% of eda's fixes) have **zero effective
adoption** in the one production consumer:

- **`mutate` has never run on eda.** No `mutate` step in eda's `build.zig`, no `[mutation]`
  config, no `.guardian/mutation.txt` ever committed. Root cause: `addAllChecks` deliberately
  excludes it (`src/build_helper.zig:21`) and guardian provides no helper to wire it — every
  consumer must hand-roll the step, so none did.
- **`change-classification` is live on eda but toothless.** It is default-on and eda never
  configured it, but (a) *any* SPEC.md edit satisfies the verdict
  (`src/checks/change_classification.zig:47`) and eda touches SPEC.md in most fix commits, and
  (b) it diffs the working tree vs HEAD, so any commit-then-build flow (and all CI on committed
  trees) sees an empty diff and passes. Result: small fixes still ship test-less
  (`846cdc7`, `8ce9836`, `deb6524`, `05935de`, `37db800` — all post-baseline, zero test changes).

Meanwhile the structural suite generates measurable friction: **39% of eda commits touch
`.guardian/`** (215 of 551), frozen spec debt grew **82 → 124 violations in six days**, and every
shape cap is relaxed 1.7–10× (file-size at 10,000 lines — 25 files now silently exceed the
1,000-line default). The friction has a verified mechanical cause (§ Finding 2) that the
additions below fix.

Recommendation order: make the shipped dynamic tier *actually bite* (items 1–3), cut the
baseline-churn tax (item 4), then land the structural fix for cap relaxation (item 5).

## Two verified mechanisms behind the friction

**Finding 1 — the refresh valve is all-or-nothing.** `GUARDIAN_UPDATE_SNAPSHOT=1` is a single
global boolean (`src/snapshot_helper.zig:28-32`) consumed independently by every snapshot check
*and* every baseline (`src/baseline.zig:223`). Refreshing to accept one intended change accepts
**everything** that drifted in the same run, across all 57 checks. This is how frozen spec debt
grew 82→124 without any single decision to accept it: each refresh silently ratified unrelated
growth.

**Finding 2 — baseline mode structurally can't hold threshold checks, so caps get raised
instead.** Shape-check violation messages embed the current metric — e.g.
`"{file}:{line}: fn {name} is {n} lines (cap {c})"` (`src/checks/function_length.zig:26-30`,
same pattern in nesting-depth, type-size, file-size). Baselines diff by exact (position-blanked)
text (`src/baseline.zig:169`). Therefore any metric change on a frozen offender — **including an
improvement** (130 → 125 lines, still over cap) — produces a line not in the baseline → `grown`
→ **build fails**. Touching any grandfathered function forces a global refresh (Finding 1). Faced
with that, eda rationally raised the global caps instead — which removed the caps from all *new*
code (25 files now over the file-size default). This one mechanism explains most of the 39%
churn and the cap-neutering, and item 5 below is its fix.

## Ranked additions

### 1. Auto-wire `mutate` into consumers + a `nightly` command — *S effort, highest leverage*

The only check that measures whether tests *bite* is unreachable by default. Zero-config is
principle #3; mutation is the one feature where guardian violated it.

- `addAllChecks` (or a sibling `addMutateSteps`) registers `zig build mutate` and
  `zig build mutate-full` steps in every consumer automatically (`Options.mutate_steps: bool =
  true`). Consumers get the fast tier for free the day they upgrade.
- Add a `nightly` command = `all` + `mutate --full` (+ future slow tiers). All three siblings
  have `nightly`; it gives `mutate-full` an obvious home (cron/CI) instead of being a step nobody
  schedules.
- Docs: one CI snippet (`GUARDIAN_AGAINST=origin/main zig build mutate` on PRs, `nightly` on a
  schedule).

Success metric: `.guardian/mutation.txt` exists in eda within a week of upgrading.

### 2. Close change-classification's two escape hatches — *S–M effort*

The gate's decision rule is `behavioral > 0 and test_lines == 0 and !spec_changed`
(`change_classification.zig:47`).

- **Tighten `spec_changed`**: currently true if SPEC.md merely appears in the diff
  (`pathListed`). Require the SPEC.md diff to *add or modify behavior bullet lines* (`- ` lines
  outside code fences), so a typo fix or section shuffle no longer waives the test requirement.
  Stronger option worth considering: spec-only changes waive the gate only when the run's spec
  check reports no *new* unlinked bullets — otherwise "add a bullet, ship no test" just moves the
  debt into the spec baseline (exactly what eda's +51%-in-6-days spec debt shows).
- **Gate the last commit when the tree is clean**: if `against` resolves to `HEAD` and the
  working-tree diff is empty, diff `HEAD~1..HEAD` instead (skip merge commits). Commit-then-build
  agents and CI-on-committed-trees are currently ungated; this closes the hole without any
  workflow change. (Item 3 closes it structurally for the local flow.)

### 3. `--intent` + safety-railed auto-commit (`guardian-check commit`) — *M effort*

Family parity and the structural fix for item 2's timing hole: when guardian itself makes the
commit, the working-tree diff it just gated is *exactly* the change being committed.

- Proven in gleam and sveltekit; the Go/Rust/Gleam guardian workflows are already
  intent-driven (`check --intent "..."` → auto-commit on green) — zig is the family outlier, and
  agent instructions for zig currently end at "run `zig build`".
- Copy sveltekit's rails (`guardian-sveltekit/src/commit.ts`), the mature implementation:
  explicit `git add -- <paths>` (never `git add .`), a forbidden-path list, always include
  `.guardian/` + SPEC.md so baseline changes ride the commit that caused them — which also makes
  baseline churn *attributable* instead of smeared across 39% of commits.
- Shape: `guardian-check commit --intent "..." [dir]` — runs `all`, on green commits staged
  work with the intent as the message; on red, prints violations and leaves the tree untouched.

### 4. Refresh granularity, baseline auto-prune, and a `debt` report — *S effort each*

Directly attacks Finding 1 and the churn tax.

- **Selective refresh**: `GUARDIAN_UPDATE_SNAPSHOT=<check[,check]>` refreshes only the named
  checks' snapshots/baselines (`=1` keeps today's accept-everything meaning). An agent accepting
  one intended API change should not be able to silently ratify spec-debt growth.
- **Auto-prune shrunk baselines**: the `shrunk` outcome currently just hints
  (`baseline.zig:271-275`); make it rewrite the baseline. Removing entries is monotone-safe,
  deletes the "re-run with the env var to prune" round-trip, and cuts a class of `.guardian/`
  churn commits.
- **`guardian-check debt`**: non-gating report — per-check baseline counts, snapshot totals,
  mutation score, sorted descending, with delta vs the last committed `.guardian/` state. Makes
  debt growth a *decision* instead of a side effect. (Optional companion:
  `[baseline] deny_growth = ["spec"]` — named checks' baselines may never grow even under
  refresh; the 1:1 spec mapping is the flagship guarantee and today it's the fastest-growing
  frozen debt.)
- **Bug found in passing**: eda commit `8cbb775` notes stale baselines "masked by inputs.sha256
  cache" — a refresh that changes only `.guardian/` re-hashes as unchanged in some sequence.
  Worth a regression test on the cache digest ordering (`.guardian/` is hashed, `cache/` excluded
  — verify the refresh-then-build path).

### 5. Per-item ratchets for threshold checks (baseline v2) — *M–L effort, the structural fix*

The caps→ratchets recommendation from 2026-07-06, now with the mechanism verified (Finding 2).

- Threshold checks (function-length, nesting-depth, type-size, file-size, complexity, params,
  struct-method-cap, optional-density, bool-ops, line-length…) emit structured records:
  **stable key** (`file` + qualified fn/type name) + **metric value**, instead of prose lines.
- Baseline v2 stores `key → value`. Fail only when a key's value **exceeds its recorded value**
  (or the default cap, for new keys). Improvements auto-lower the recorded value. Deleted keys
  auto-prune.
- Effect: legacy offenders are grandfathered *individually* and can only shrink; new code gets
  the strict default; touching a grandfathered function no longer reds the build or forces a
  global refresh. eda could then drop `max_file_lines = 10000` back to 1,000 and the 25
  currently-invisible oversized files would each get a personal ceiling.
- This also resolves the severity-tier debate on principle #2's terms: research says
  build-breaking style gates get routed around (eda confirmed it twice), but per-item ratchets
  keep every check a hard block while blocking only *regression* — no warn tier needed.
  (FRAMEWORK.md's designed-but-unbuilt "soft rules that warn" layer can stay unbuilt.)

### 6. Structured violations: wire the dead `Violation` struct + JSONL sink — *M effort*

`reporter.Violation { file, line, message, fix_hint }` exists and is used by zero checks
(`reporter.zig:11-16`); every check hand-formats prose, and `baseline.extract` then re-parses
that prose by scraping indentation (`baseline.zig:40-56`) — an invisible coupling where any
format tweak corrupts baselines.

- Migrate checks to emit `Violation` (mechanical; can go check-by-check). Baseline capture
  becomes structured records instead of scraped text — which is also the prerequisite for
  item 5's `key → value` records.
- Emit `.guardian/last-run.jsonl` (or `--format json`): one record per violation
  `{check, file, line, message, fix_hint}` + a run summary. Guardian is AI-first; today the
  agent's fix loop is "re-read stderr prose." Machine-readable violations enable precise
  agent auto-fix loops, editor integration, and the `debt` report for free. No sibling has this —
  and the siblings are frozen; this repo is where the family innovates now.

### 7. CLI ergonomics cluster: `explain`, `--only/--skip`, `--version` — *S effort*

- **`guardian-check explain <check>`** — the registry has one-line summaries; add a long-form
  rationale per check: *why it blocks, how to fix, how to exempt (`[[allow]]`/config), when to
  disable*. An agent (or human) hitting a violation gets the recipe in-terminal instead of
  guessing — the cheapest known lever against route-arounds. (No sibling has it; net-new.)
- **`all --skip <names>` / `--only <names>`** — gleam + sveltekit parity. Single-check runs
  exist; skip/only makes agent iteration on one failure cheap without config edits.
- **`--version`** — trivial; print in run headers so `.guardian/` diffs are attributable to
  guardian upgrades.

### 8. Proven sibling checks worth porting (all opt-in) — *S–M each*

- **Completeness checklist** (gleam + rust ship the identical 8 categories: empty inputs, large
  inputs, unauthorized, I/O failure, concurrent, malformed encoding, integer overflow,
  panic-free). As an opt-in spec-side check: each SPEC.md feature section must address (or
  explicitly waive) each category. eda's dominant shipped-bug classes — boundary/geometry/
  numeric — are exactly what "empty/large/overflow" bullets force tests for.
- **Skipped-test ban** (sveltekit's todo/skip gate, zig-flavored): a test whose body is
  unconditionally `return error.SkipZigTest` (or empty) still satisfies its `// spec:` tag — a
  hole in the flagship 1:1 guarantee. Token-level check; conditional skips
  (`if (!have_fixture) return error.SkipZigTest;`) stay legal.
- **DORA sink** (gleam + rust): append-only JSONL of `{timestamp, branch, commit, outcome,
  duration}` per run. Non-gating, ~50 lines, and it's the data source the `debt` report and any
  future trend analysis want.

### 9. Mutation engine hardening (for when item 1 lands) — *M effort*

Pre-empt the adoption-killers before the first consumer relies on it:

- **Small-diff gating floor**: the fast tier fails below `min_score_pct` regardless of sample
  size — a 2-mutant diff with 1 survivor is a 50% red build. Gate on percentage only at
  `n ≥ min_mutants` (else report survivors without failing, or fail only on `survivors > k`).
- **Per-mutant result cache** keyed on (file digest, mutant span/op, suite digest): unchanged
  mutants skip the build+test cycle; repeated fast-tier runs become incremental.
- **Parallel mutants**: today mutants splice the real tree in place and run sequentially
  (`mutation/runner.zig:113`, `cli/mutate.zig:120-148`). Copy-tree sandboxes (or git worktrees)
  would parallelize `--full` across cores like the check runner already does.
- **Survivor report for agents**: file:line, the spliced operator, and the original line — the
  exact prompt an agent needs to write the killing test. (Pairs with item 6's JSONL.)
- **Equivalent-mutant waiver**: `>` ↔ `>=` on min/max-style scans is a known noise class; support
  a `// mutate-ok: boundary` line waiver rather than operator-level suppression.

### 10. `guardian.fakes` module — *M effort, lower priority*

The ban-* family forces ports (`infra/clock`, `infra/random`, `infra/fs`…) but guardian supplies
nothing to put behind them — rust-guardian ships `guardian::fakes::*` (clock/rng/fs/net) for
exactly this. A small `guardian.fakes` namespace (FakeClock, SeededRandom, FakeFs, FakeEnv)
completes the story: the check tells you to inject; the library hands you the deterministic test
double. Also the natural seed for future property-test scaffolding.

## Speculative / nightly-tier (not ranked)

- **Fuzz smoke** on Zig's built-in fuzzer (`zig build test --fuzz`, bounded seconds) as a
  `nightly` stage. eda *deleted* its hand-rolled fuzz harness — turnkey beats hand-rolled.
  Blocked mainly on the fuzzer's maturity in 0.15.
- **Regression-corpus / differential-replay convention** (rust parity): `[corpus]` config naming
  a replay step guardian runs in `nightly`. For eda's geometry bugs, golden replay is the natural
  test form; guardian can standardize the harness without understanding the domain.
- **Non-gating LLM spec↔test semantic audit** (nightly): the 1:1 mapping is nominal — nothing
  links tag text to what the test body actually asserts. Static checks can't close this; a
  scheduled agent pass can flag "tag says X, test asserts Y" without blocking builds.

## Anti-recommendations (reaffirmed)

- **No new shape/style hard-block checks.** eda relaxed every shape cap and disabled the two
  noisiest checks; adding more of that class grows the route-around, not the protection.
  (Item 5 is the productive direction for this energy.)
- **No warn/advisory tier.** It contradicts principle #2, no sibling models one, and per-item
  ratchets (item 5) deliver the intended effect — block regressions, tolerate history — inside
  hard-block semantics.
- **Don't fold `mutate` into `all`.** Per-mutant build+test cycles are too slow for every build;
  the fix is wiring + `nightly` (item 1), not gating.

## Suggested sequencing

1. **Items 1 + 2 + 4** (auto-wire mutate, close the escape hatches, selective refresh +
   auto-prune) — small, independent, and together they convert the already-built dynamic tier
   from "shipped" to "load-bearing."
2. **Item 3** (`--intent` commit) — brings zig into the family workflow and structurally fixes
   the diff-timing hole.
3. **Items 6 → 5** (structured violations, then baseline v2 per-item ratchets) — 6 is the
   mechanical prerequisite; 5 is the biggest architectural payoff.
4. **Items 7–9** opportunistically; 10 + speculative tier when the above are absorbed.
